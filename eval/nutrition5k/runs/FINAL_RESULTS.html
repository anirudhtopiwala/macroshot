MacroShot - meal-macro accuracy eval

How accurately can an LLM read calories & macros from a meal photo (and/or a typed description)? Benchmarked on Nutrition5K against the published baseline of Wang et al. 2026, n=100 dishes stratified by complexity. Lower error is better.

Key takeaways
  • The photo is the single biggest lever. With the same user caption, adding the image cut error by ~53% (Flash-Lite) / ~55% (Opus 4.8).
  • Extra information only helps if the prompt knows what to do with it. Handing the generic prompt the true ingredient list made it worse (+36% / +15%) - it stacks standard servings. Giving MacroShot the user’s caption made it better (−13% / −13%).
  • Photo-free text logging still works. With no image, detailed typed descriptions land within ~63% (Opus) / ~95% (Flash-Lite) median error - rough, but far better than nothing.
  • The frontier model (Opus) is more accurate, but the same patterns hold on the cheap shipped model - at ~68× the cost per meal, which is why the cheap model ships.

A daily user (3 meals/day, 90/month) costs ~$0.05/month on Flash-Lite vs ~$3.33/month on Opus - ~68× for roughly a dozen points better median error. Flash-full costs ~3.6× Flash-Lite while scoring worse on the shipped flow (its chain-of-thought over-estimates portions). For a free consumer app the cheap model + the right prompt is the rational ship; the frontier model is a quality ceiling, not a cost-effective default. Prompt caching / batch can cut Opus by up to ~90% / 50%.

Methodology & definitions

Metrics

MAE - Mean Absolute Error
Average |prediction − ground truth| in native units (kcal / grams). Primary, most interpretable.
RelErr - Relative Error (MAPE)
mean(|pred − truth| / truth) × 100%. Scale-free but inflated by tiny denominators.
MedPE - Median Percent Error
median(|pred − truth| / truth) × 100%. Robust counterpart - 'half of dishes within X%'. Best single UX number.
Avg*
Averaged across the five nutrients (calories, mass, fat, carbs, protein).

Generic baseline prompt
Calculate the total calories (kcal), total weight (g), fat content (g), carbohydrate content (g), and protein content (g) for the food in this image. Reply with JSON only: {"calories": <kcal>, "mass_g": <g>, "fat_g": <g>, "carb_g": <g>, "protein_g": <g>}.

[+ GT ingredients prepends: "Ingredients on this plate: <names>."]
How the user captions were generated

Each caption was generated by Gemini from the dish’s ground-truth ingredient list: a casual log entry, no exact grams/macros leaked, literal, sub-1 g seasonings skipped. The generator does see each ingredient’s gram weight and uses it for the detailed caption’s vague portion cues ('a good portion') - never a number - so 'detailed' carries a mild GT-derived portion hint 'terse' does not. Verified faithful (≈76% coverage, ~0 hallucinations).

Ground-truth ingredients (input to Gemini)
corn; garlic; caesar salad; nopales; olive oil; pepper; green beans; lime; sour cream; jicama; arugula; fish; carrot
→ Terse caption
“Had fish with caesar salad, green beans, corn, and some other veggies.”
→ Detailed caption
“Had a good portion of fish, a side of caesar salad, and green beans. Also a small mix of corn and other veggies, with olive oil, lime, and sour cream.”
Method: Nutrition5K (Thames et al. 2021) camera-C frame 10, n=100 stratified (seed 42). Frontier-model runs use one isolated, ground-truth-free sub-agent per dish. Baseline = our reconstruction of Wang et al. 2026’s prompt. Caveats: cafeteria/single-cuisine heavy; RelErr noisy (prefer MAE / MedPE); Flash-full runs with chain-of-thought on; some Opus-4.8 cells may be small-n previews.
